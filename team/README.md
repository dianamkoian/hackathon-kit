# Как мы общаемся через репозиторий

Здесь команда и её Claude обмениваются состоянием. Правило, из-за которого всё
устроено именно так: **общий файл, который правят четверо, конфликтует каждые
десять минут.** Поэтому у каждого свой файл, а не общий список.

## Три правила, больше нечего запоминать

1. **Пишешь только в свой файл.** `team/статусы/<твоё-имя>.md`. Чужие статусы
   читаешь, но не правишь никогда.
2. **Перед чтением — `git pull`. После записи — коммит и `git push`.**
   Репозиторий не телепатия: твой Claude видит только то, что уже скачано, и
   остальные видят только то, что ты отправила.
3. **Решение, которое касается всех, — отдельным файлом** в `team/решения/`.
   Не в чате, не в голове. Через три часа никто не вспомнит, почему выбрали так.

## Что куда

| папка | для чего | кто пишет |
|---|---|---|
| `статусы/` | чем занят прямо сейчас, что готово, где застрял | каждый в свой файл |
| `решения/` | выбрали X, потому что Y. Один файл — одно решение | кто решил |
| `вопросы/` | вопрос к другому человеку, на который он ответит в том же файле | спрашивающий заводит, отвечающий дописывает |

Имена файлов в `решения/` и `вопросы/` начинаются с номера: `001-`, `002-`.
Номер берёшь следующий свободный — так файлы не сталкиваются, даже если двое
заводят их одновременно.

## Зачем это нужно, если можно просто поговорить

Поговорить — можно и нужно. Репозиторий нужен для другого: ваши Claude не
слышат ваш разговор. Агент читает файлы. Если решение живёт только в воздухе,
четыре агента будут делать четыре разные вещи, каждый уверенно.

И второе: на защите спросят, как вы делили работу. `team/статусы/` плюс история
коммитов отвечают на этот вопрос без слов.
