# 031. git pull и перезапуск uvicorn: схема «руководитель просит»

**От:** Соня
**Кому:** дима (зона: api/, деплой)
**Статус:** сделана — второй пример на живой модели расходится

## Что сделать
На машине с рабочей ссылкой: `git pull`, затем перезапустить только uvicorn, cloudflared не трогать. Коммит 3c825c5. После перезапуска на ссылке: «Привет, это Лена из бухгалтерии. Директор просит срочно оплатить счёт поставщику сегодня до пяти, реквизиты новые, пришлю в личку. Только никому пока не говори.» должно давать «не доверять» и C06; «Мам, я задержусь на тренировке, буду дома в восемь. Купить хлеба?» — не «паузу» C12, а «приёмов не найдено».

## Зачем
Пока модель занята, отвечают детекторы; без новых правил они давали C18 на схеме с руководителем и C12 на бытовом сообщении.

## Как понять, что готово
Оба примера на рабочей ссылке дают ответы выше; туннель не перезапускался.

## Ответ
**Перезапуск сделан** (Дима, 25.10 ~16:45). `git pull` до `397d271`, смоук
проходит, перезапущен только uvicorn, туннель не трогал — адрес тот же.
Через ссылку, модель свободна:

- «Мам, я задержусь… Купить хлеба?» — `mechanical`, `doubt`, `C00`, «приёмов
  не найдено», без паузы C12. ✔
- «Лена из бухгалтерии… Директор просит…» — **`abstained`**, живая модель
  `qwen2.5:7b`, 7 с. Причина в trace: «признак без маркера: markers[].type: no
  'authority' for authority_request 'Директор просит…'» — детектор нашёл
  просьбу руководителя, модель этот маркер не назвала, барьер `check_signals`
  отклонил ответ → отказ. До C06 дело не доходит: новое правило работает в
  механике (модель занята или недоступна), а при свободной модели отвечает
  каскад.

Деплой ни при чём. Если нужно, чтобы и при живой модели было «не доверять /
C06», — это правило после модели в `domains/` (как `news_rule`), твоё решение.

## Дополнение, 16:45

Ещё правка `526dffd`: если каскад отказался, а признаки в тексте есть, отвечает механика (C06, C11, C20…), отказ каскада виден в trace как `cascade_abstain`. Один `git pull` и один перезапуск uvicorn покрывают обе правки, cloudflared не трогать.
