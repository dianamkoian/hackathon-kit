## Что я проверила сама, а не по чужому файлу

Прогнала `python3 -m evals.run` на спеке `authenticity`, 30 примеров. Числа
воспроизвелись в точности:

| вариант | точность (где ответил) | неверных выдано | $/кейс |
|---|---|---|---|
| baseline | 93.3% | 2 | $0.00504 |
| каскад | **100%** | **0** | **$0.00270** |

Ноль неверных ответов при 93% покрытия — это сильно. Два сообщения из
тридцати уходят в отказ, и по ним продукт выдаёт проверку из каталога, а не
молчит. Именно это и надо показывать жюри.

`README.md` — таблицу чисел привела к прогону. Остальной текст README не

## Что добавила в общую обвязку

- `.githooks/pre-push` — перед пушем прогоняется смоук и сверка чисел в README.
  Включается командой `bash scripts/setup.sh` (один раз после клонирования).
  Аварийный выход: `SKIP_CHECKS=1 git push`.
- `scripts/check_readme_numbers.py` — сверяет таблицу в README с прогоном.
  Правило «числа только из прогона» теперь проверяет машина, а не совесть.
- `scripts/setup.sh` — один вход после клонирования: хуки, проверка имени в
  коммитах, прогон.

## Урок, который стоит знать всем

Я закоммитила `evals/report.md`, сгенерированный не мной, потому что
использовала `git add -A`. В общем репозитории это опасно: забирает чужие
изменения в твой коммит с твоим сообщением. **Добавляйте файлы по именам**, а
не `-A`.
